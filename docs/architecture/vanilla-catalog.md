# Catalog-only saved routing — M1 issue 9

The pack owns 46 Vanilla surface targets in a fixed 140-holder fresh-world pool, with initial Vanilla normal weight 1 / priority 0 alongside unchanged Terralith entries. The user approved this design and the measured three-seed, Scale-1/2 distribution/appearance on 2026-10-26. The catalog adds zero fallback entries; an uncovered context produces an explicit error. Existing saved policies retain their accepted behavior. Delivery identities and full evidence are recorded by the paired [pack issue](https://github.com/Ultiraden/ulti-world/issues/9).

`SavedSelectionPolicy` keeps its accepted four-argument compatibility constructor and adds an explicit routing value. Version1 policy JSON retains its original fields with absent routing. Version2 requires `routing:catalog-only-v1`; unknown combinations fail. Prior version1-only runtimes reject version2. `cellular-v1` geometry and1024-world-block spacing remain unchanged; a new world's sorted140-ID pool is fixed for its lifetime.

In the new mode `BiomeClassifier` applies the generic selector to land, ocean and final-wet river contexts. An eligible positive catalog entry supplies every surface identity. It never calls the transitional river program, Java Vanilla classifier or inactive legacy placement path. A missing choice throws with owning seed/scale, column, revision, catalog digest, environment and no-match reason. There is no automatically chosen substitute biome. Existing legacy and version1 generic dispatch remains unchanged.

`WorldClassificationPublication` rejects inactive/disabled initial strict bindings and invalid owning-holder/pool proposals. A disabling reload rejects atomically while a strict world is bound, retaining the previous controller state. An active but empty/zero-weight/uncovered catalog can be valid metadata but cannot generate a matching tile: failure is explicit, never a partial successful biome tile. Pending and cached work retain their captured publication. Saved pool expansion requires a new world.

The pack owns ecological entries and normal weights. Schema-v1 fallback-tier support remains available for explicitly authored data, but no new fallback entries or Java fallback identity are added by this route. Surface-rule importing, cave classification, environmental equations, hydrology and Layer-3 content remain separate. The existing pool retains cave/compatibility holders without admitting them as new Vanilla surface candidates.

Validation covers production codec roundtrips/rejections, disabled/invalid bindings, atomic reload rejection, strict frozen-wet/ocean dispatch, and empty/zero-weight failures. A 24-window CPU replay covers 25,165,824 columns with exact raw34/snow/frozen-legacy parity. Actual CUDA normal generation at both scales matches complete million-column CPU biome/snow references and accepted physical fields. Both scales pass owning Holder/feature sorting, pending/completed retention, failure cleanup/recovery and saved-world reopening. Fresh inactive/disabled bindings reject before ordinary startup. Windows and CUDA artifacts reproduce byte-for-byte from clean source archives under strict dependency verification. Synthetic reachability is not native feature certification; FULL spawn checks are bounded smoke tests, and the selected maps are not global rarity estimates.
