# Catalog-only saved routing — M1 issue 9 candidate

Candidate source for ulti-world #9. Human approval on 2026-10-26 covers a separate fresh-world catalog-only mode, 46 Vanilla surface targets /140 supported holders, and initial Vanilla normal weight1 /priority0 alongside unchanged Terralith entries. The user's latest direction requires limiting fallback behavior; the pack candidate adds zero fallback entries. Distribution/appearance and native/build/release acceptance remain required. This source is not yet a published TD_m1.8 delivery.

`SavedSelectionPolicy` keeps its accepted four-argument compatibility constructor and adds an explicit routing value. Version1 policy JSON retains its original fields with absent routing. Version2 requires `routing:catalog-only-v1`; unknown combinations fail. Prior version1-only runtimes reject version2. `cellular-v1` geometry and1024-world-block spacing remain unchanged; a new world's sorted140-ID pool is fixed for its lifetime.

In the new mode `BiomeClassifier` applies the generic selector to land, ocean and final-wet river contexts. An eligible positive catalog entry supplies every surface identity. It never calls the transitional river program, Java Vanilla classifier or inactive legacy placement path. A missing choice throws with owning seed/scale, column, revision, catalog digest, environment and no-match reason. There is no automatically chosen substitute biome. Existing legacy and version1 generic dispatch remains unchanged.

`WorldClassificationPublication` rejects inactive/disabled initial strict bindings and invalid owning-holder/pool proposals. A disabling reload rejects atomically while a strict world is bound, retaining the previous controller state. An active but empty/zero-weight/uncovered catalog can be valid metadata but cannot generate a matching tile: failure is explicit, never a partial successful biome tile. Pending and cached work retain their captured publication. Saved pool expansion requires a new world.

The pack owns ecological entries and normal weights. Schema-v1 fallback-tier support remains available for explicitly authored data, but no new fallback entries or Java fallback identity are added by this candidate. Surface-rule importing, cave classification, environmental equations, hydrology and Layer-3 content remain separate. The existing pool retains cave/compatibility holders without admitting them as new Vanilla surface candidates.

Candidate gates include production codec roundtrips/rejections, disabled/invalid binding and atomic reload checks, strict empty/zero/frozen-wet/ocean dispatch, complete old-policy parity and new-mode raw34/snow comparisons, and product-data endpoint/synthetic-reachability tests. Synthetic contexts and copied CPU classifiers are not native-world or feature certification. Owning Minecraft generation, source decoding/feature sorting, saved reopen, cache/pending and failure-completion tests at scales1/2 remain required before merge, together with measured appearance review and reproducible Windows/CUDA delivery.
